# Личный финансовый план (ЛФП)

Конфигурация 1С:Предприятие для учёта и планирования личных финансов: доходы/расходы,
цели накоплений, инвестиции, счета и кошельки.

Платформа: 8.3.27 (режим совместимости `Version8_3_24`), управляемое приложение.
Конфигурация выгружена в текстовом виде («Выгрузка конфигурации в файлы» из Конфигуратора)
в каталог `src/` — это основной источник истины, редактируется через Конфигуратор/EDT.

## Структура

- `Catalogs/` — справочники: Пользователи, Цели, КошелькиИСчета, Инвестиции, СтатьиДДС.
- `Documents/` — документы: ИзменениеБаланса, ПлановаяОперация.
- `AccumulationRegisters/` — регистры накопления: Оборот, ПлановыеДвижения.
- `InformationRegisters/` — регистры сведений: ДостижениеЦелей, ДоходностьПоИнвестициям, Календарь.
- `DataProcessors/` — обработки: ЛичныйФинансовыйПлан (дашборд), СозданиеПлановыхОпераций.
- `CommonModules/` — общие модули с серверной бизнес-логикой.
- `Constants/` — константы конфигурации.

## Архитектурные соглашения

**Бизнес-логика — в общих модулях, а не в модулях форм.** Формы должны оставаться
тонкими: получать данные и передавать их в диаграммы/таблицы. Расчёты, запросы и
заполнение диаграмм выносятся в серверные общие модули (например, `ЛФПСервер`) —
так их проще переиспользовать и тестировать отдельно от конкретной формы.

**Текущий пользователь.** Конфигурация сейчас рассчитана на одного пользователя.
Кто им является — задаётся константой `ТекущийПользователь` (ссылка на
`Справочник.Пользователи`), а не поиском по имени в коде. Получать его нужно через
`ЛФПСервер.ТекущийПользователь()`, а не напрямую через константу — если позже
понадобится многопользовательский режим (сопоставление с пользователем ИБ,
права доступа), это единственное место, которое придётся поменять.

Важно: справочник `Цели` (и связанные с ним регистры) пока не имеет привязки к
пользователю — при добавлении многопользовательского режима это нужно будет
учесть в первую очередь.

## Известные ограничения

- Нет автотестов и CI — конфигурация небольшая, проверяется вручную через тонкий клиент.
- Однопользовательский режим: переключение пользователя в форме дашборда пересчитывает
  диаграммы, но выбор пользователя не влияет на видимость данных (Цели общие для всех).
