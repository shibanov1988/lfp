# Автозагрузка конфигурации из git в базу 1С

После `git pull`/переключения ветки конфигурация из `src/` автоматически
загружается в локальную базу через `1cv8.exe DESIGNER /LoadConfigFromFiles`.
Работает только локально, на машине с установленным 1С:Предприятие (Windows).

## Установка (один раз на машину)

1. Скопируйте `tools/deploy/Update-1C.local.example.txt` в
   `tools/deploy/Update-1C.local.txt` (этот файл в `.gitignore`, не коммитится)
   и заполните под свою машину: путь к `1cv8.exe`, строку подключения к базе,
   пользователя/пароль ИБ. Это обычный текстовый файл `Ключ=Значение`, а не
   `.ps1` — специально, чтобы кириллица в пути к базе не зависела от того, в
   какой кодировке его сохранит редактор.
2. Подключите хуки из репозитория:
   ```
   git config core.hooksPath tools/git-hooks
   ```
   Команда локальная — выполняется один раз для каждого клона репозитория,
   через git не тиражируется автоматически.
3. Проверьте вручную, что загрузка вообще работает, прежде чем полагаться на хук:
   ```
   pwsh tools/deploy/Update-1C.ps1
   ```
   (или `powershell -File tools/deploy/Update-1C.ps1`)

## Как это работает

- `git config core.hooksPath tools/git-hooks` переключает git на хуки из
  этой папки репозитория вместо `.git/hooks` (которая не версионируется).
- `post-merge` и `post-checkout` сравнивают старое и новое состояние веток;
  если изменения затронули `src/`, вызывают `Update-1C.ps1`.
- `Update-1C.ps1` запускает Конфигуратор в пакетном режиме:
  `/LoadConfigFromFiles src /UpdateDBCfg` — загружает XML-выгрузку и сразу
  применяет её к базе.

## Обратное направление: выгрузка своих изменений в git

Если вы правите конфигурацию сами в Конфигураторе (не через этот чат),
`push.bat` в корне репозитория выгружает текущее состояние базы в `src/`,
показывает `git status`, спрашивает сообщение коммита и пушит:

```
push.bat
```

Использует тот же `Update-1C.local.txt`, что и `Update-1C.ps1` — отдельная
настройка не нужна, если `pull.bat` уже работает. Под капотом —
`tools/deploy/Dump-1C.ps1`, который вызывает
`1cv8.exe DESIGNER ... /DumpConfigToFiles src`. В отличие от загрузки,
выгрузке не нужен монопольный доступ к базе — можно выгружать, не закрывая
клиент 1С (но не одновременно с другим открытым Конфигуратором той же базы).

## Известные ограничения

- **База должна быть закрыта** в клиенте 1С (и в другом Конфигураторе) в
  момент запуска — `/UpdateDBCfg` требует монопольного доступа, иначе команда
  упадёт с ошибкой захвата.
- Хук выполняется молча в фоне; если загрузка упадёт (неверный путь к
  `1cv8.exe`, база занята, ошибка конфигурации), сообщение об ошибке появится
  в выводе git после `pull`, но пройти мимо него легко. Если после `pull` база
  не обновилась — проверьте вручную командой из шага 3.
- Работает только на Windows с Git for Windows (хуки — обычные POSIX-шеллы,
  Git for Windows выполняет их через свой bash).
- `Update-1C.ps1` сам написан только на ASCII (без кириллицы) — это защита от
  той же проблемы кодировки на случай, если Windows PowerShell 5.1 на вашей
  машине снова попытается прочитать файл не как UTF-8.
- Эта настройка не тестировалась на реальной машине с 1С — если увидите
  ошибку при первом запуске `Update-1C.ps1` (например, из-за формата
  командной строки 1cv8.exe в вашей версии платформы), пришлите текст ошибки.
